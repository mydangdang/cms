# BMS 后台管理系统 - 数据库设计

> **版本**：v3.1
> **更新日期**：2026-02-13
> **设计理念**：动态权限驱动架构 + 统一权限模型 + 企业级扩展

---

## 📋 设计原则

### 核心原则
- ✅ **RBAC 权限模型**：基于角色的访问控制（管理员 ↔ 角色 ↔ 权限）
- ✅ **统一权限模型**：菜单 + 路由 + 按钮三合一，实现动态权限驱动架构
- ✅ **功能权限精细化**：支持页面级、按钮级、接口级权限控制
- ✅ **操作审计追溯**：完整的操作日志和登录日志记录
- ✅ **企业级扩展**：支持定时任务、系统配置、动态缓存

### 数据库设计规范

#### 1. 命名规范（强制）

```sql
-- 表名: bms_ 前缀 + 复数形式 + 小写
bms_admins, bms_roles, bms_permissions

-- 主键: {表单数}_id
admin_id, role_id, permission_id

-- 索引命名
PRIMARY KEY pk_admin_id (admin_id)
UNIQUE KEY uk_username (username)
KEY idx_status (status)

-- 关联表命名: {表1}_{表2} (按字母顺序)
bms_admin_roles       -- 管理员-角色
bms_role_permissions  -- 角色-权限
```

#### 2. 字段类型（强制）

```sql
-- 时间字段: 使用 INT(11) 存储时间戳
created_at INT(11) NOT NULL
updated_at INT(11) NOT NULL
deleted_at INT(11) NOT NULL

-- 布尔值: 使用 TINYINT(1)
status TINYINT(1) NOT NULL DEFAULT 1  -- 0禁用 1正常
is_super TINYINT(1) NOT NULL DEFAULT 0

-- 小数: 使用 DECIMAL
amount DECIMAL(10, 2)

-- 禁止 FLOAT/DOUBLE 存储金额
```

#### 3. SQL 编写规范（强制）

```sql
-- ❌ 禁止 SELECT *
SELECT * FROM bms_admins;

-- ✅ 明确指定字段
SELECT admin_id, username, status FROM bms_admins;

-- ❌ 禁止 WHERE 中使用函数
WHERE DATE(created_at) = '2026-02-05'

-- ✅ 使用范围查询
WHERE created_at >= UNIX_TIMESTAMP('2026-02-05')
  AND created_at < UNIX_TIMESTAMP('2026-02-06')

-- ❌ 禁止外键约束
FOREIGN KEY (role_id) REFERENCES bms_roles(role_id)
```

#### 4. BMS 项目约定

```sql
-- 状态值约定
status: 0=禁用/失败, 1=启用/成功
is_super: 0=否, 1=是
deleted_at: 0=否, >0是
```

#### 5. 存储引擎和字符集约束（强制）

```sql
-- ✅ 所有表必须使用 InnoDB 存储引擎
ENGINE=InnoDB

-- ✅ 字符集统一使用 utf8
DEFAULT CHARSET=utf8

-- ✅ 排序规则统一使用 utf8_general_ci
COLLATE=utf8_general_ci
```

**约束说明**：
- **存储引擎**：所有表必须使用 `InnoDB`，支持事务和外键
- **字符集**：统一使用 `utf8`，支持中文
- **排序规则**：`utf8_general_ci` 不区分大小写排序

**建表示例**：
```sql
CREATE TABLE `bms_admins` (
  `admin_id` INT(11) NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `username` VARCHAR(50) NOT NULL COMMENT '用户名',
  PRIMARY KEY (`admin_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8 COLLATE=utf8_general_ci COMMENT='管理员表';
```

### 3. 权限菜单表 (bms_permissions) 🔥 核心创新

**统一权限模型**：菜单 + 路由 + 按钮三合一设计，实现真正的动态权限驱动架构。

| 字段名 | 类型 | 长度 | 允许NULL | 默认值 | 说明 |
|--------|------|------|----------|--------|------|
| permission_id | INT | 11 | NO | AUTO_INCREMENT | 主键ID |
| parent_id | INT | 11 | YES | 0 | 父级ID（0表示顶级） |
| title | VARCHAR | 50 | NO | | 权限标题（中文显示） |
| code | VARCHAR | 100 | YES | NULL | 权限标识（如：system:admin:add） |
| type | TINYINT | 4 | NO | | 类型：1=目录,2=菜单,3=按钮,4=接口 |
| path | VARCHAR | 200 | YES | NULL | 前端路由路径 |
| component | VARCHAR | 200 | YES | NULL | 前端组件路径 |
| icon | VARCHAR | 50 | YES | NULL | 图标（Element Plus 图标名） |
| is_hidden | TINYINT | 4 | YES | 0 | 是否隐藏：0=显示,1=隐藏 |
| is_affix | TINYINT | 4 | YES | 0 | 是否固定标签：0=否,1=是 |
| is_cache | TINYINT | 4 | YES | 0 | 是否开启 KeepAlive 缓存：0=否,1=是 |
| sort_order | INT | 11 | YES | 0 | 排序（数字越小越靠前） |
| status | TINYINT | 4 | YES | 1 | 状态：0=禁用,1=启用 |
| created_at | INT | 11 | NO | | 创建时间（时间戳） |
| updated_at | INT | 11 | NO | | 更新时间（时间戳） |
| deleted_at | INT | 11 | NO | 0 | 删除时间（时间戳） |

**索引：**
```sql
PRIMARY KEY (`permission_id`)
KEY `idx_parent_id` (`parent_id`)
KEY `idx_type` (`type`)
KEY `idx_status` (`status`)
KEY `idx_code` (`code`)
KEY `idx_deleted_at` (`deleted_at`) USING BTREE
```

**建表语句：**
```sql
CREATE TABLE `bms_permissions` (
  `permission_id` INT(11) NOT NULL AUTO_INCREMENT COMMENT '权限ID',
  `parent_id` INT(11) DEFAULT '0' COMMENT '父级权限ID（0为顶级）',
  `title` VARCHAR(50) NOT NULL COMMENT '权限标题（中文显示）',
  `code` VARCHAR(100) DEFAULT NULL COMMENT '权限编码（如：system:admin:add）',
  `type` TINYINT(4) NOT NULL COMMENT '1=目录,2=菜单,3=按钮,4=接口',
  `path` VARCHAR(200) DEFAULT NULL COMMENT '前端路由路径',
  `component` VARCHAR(200) DEFAULT NULL COMMENT '前端组件路径',
  `icon` VARCHAR(50) DEFAULT NULL COMMENT '图标（Element Plus 图标名）',
  `is_hidden` TINYINT(4) DEFAULT '0' COMMENT '是否隐藏（0=显示,1=隐藏）',
  `is_affix` TINYINT(4) DEFAULT '0' COMMENT '是否固定标签（0=否,1=是）',
  `is_cache` TINYINT(4) DEFAULT '0' COMMENT '是否开启 KeepAlive 缓存（0=否,1=是）',
  `sort_order` INT(11) DEFAULT '0' COMMENT '排序（数字越小越靠前）',
  `status` TINYINT(4) DEFAULT '1' COMMENT '状态（0=禁用,1=启用）',
  `created_at` INT(11) NOT NULL COMMENT '创建时间（时间戳）',
  `updated_at` INT(11) NOT NULL COMMENT '更新时间（时间戳）',
  `deleted_at` INT(11) UNSIGNED NOT NULL DEFAULT '0' COMMENT '删除时间（时间戳）',
  PRIMARY KEY (`permission_id`),
  KEY `idx_parent_id` (`parent_id`),
  KEY `idx_type` (`type`),
  KEY `idx_status` (`status`),
  KEY `idx_code` (`code`),
  KEY `idx_deleted_at` (`deleted_at`) USING BTREE
) ENGINE=InnoDB DEFAULT CHARSET=utf8 COMMENT='权限菜单表';
```

**统一权限模型设计说明：**

```
┌─────────────────────────────────────────────────────────────┐
│                    bms_permissions 表                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  type = 1 (目录)                    type = 2 (菜单/页面)     │
│  ┌──────────────┐                ┌──────────────┐          │
│  │ 系统管理      │                │ 管理员管理    │          │
│  │ path: /system│                │ path: admin  │          │
│  │ icon: Setting│                │ component:   │          │
│  └──────────────┘                │   @/views/   │          │
│         │                        │   admin/     │          │
│         └────────────────────────│   index.vue  │          │
│                                  └──────────────┘          │
│                                          │                  │
│                                          ▼                  │
│                              type = 3 (按钮)                │
│                              ┌──────────────┐              │
│                              │ 新增按钮      │              │
│                              │ code: admin: │              │
│                              │   create     │              │
│                              └──────────────┘              │
│                                                             │
│  type = 4 (接口) - 可选的细粒度 API 权限控制                │
│  ┌────────────────────────────────┐                        │
│  │ code: POST /admin/admin/add   │                        │
│  └────────────────────────────────┘                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘

前端动态生成逻辑：
1. 根据 type=1,2 构建菜单树
2. 根据 path 和 component 动态生成路由
3. 根据 type=3 生成按钮权限控制
4. 根据 is_hidden 控制菜单显示状态
```

## 🎯 权限类型约定

### 统一权限命名规范

| type 值 | 说明 | code 命名规则 | 示例 code |
|-------|------|-------------|-----------|
| 1 | 目录 | {模块名} | Workspace, System |
| 2 | 菜单 | {模块名}:{功能名} | system:admin |
| 3 | 按钮 | {模块名}:{功能名}:{操作} | system:admin:add |
| 4 | 接口 | {模块名}/{控制器名}/{方法名} | admin/admin/add |

**详细命名规则**：
- **目录（type=1）**：模块名称，如 `Workspace`、`System`
- **菜单（type=2）**：`模块名:功能名`，如 `system:admin`、`system:role`
- **按钮（type=3）**：`模块名:功能名:操作`，如 `system:admin:add`、`system:admin:edit`、`system:admin:delete`
- **接口（type=4）**：`模块名/控制器名/方法名`，如 `admin/admin/add`、`admin/role/edit`

**按钮 权限规则说明**：
- 格式：`{路由文件夹}:{路由页面}:{操作类型}`
- 路由文件夹：对应 src/views/ 目录（如 /src/views/system → system）
- 路由页面：对应路由path中页面（如 /system/admin → admin）
- 操作类型：对应操作（如 add、edit、delete）
- 
**API 权限规则说明**：
- 格式：`{模块名}/{控制器名}/{方法名}`
- 模块名：对应 ThinkPHP 的模块目录（如 admin）
- 控制器名：对应控制器文件名（如 Admin.php → admin）
- 方法名：对应控制器内的方法名（如 add、edit、delete）

**代码示例对比**：

## 🎯 关键设计说明

### 统一权限模型（菜单+路由+按钮三合一）

这是本设计的核心创新点，实现了**真正的动态权限驱动架构**：

1. **一张表管理所有权限相关**：菜单、路由、按钮权限全部在 `bms_permissions` 表中
2. **前端完全由后端数据驱动**：
   - 动态生成菜单树
   - 动态生成路由配置
   - 动态控制按钮显示/隐藏

3. **权限类型说明**：
   - `type=1`：目录（ Sidebar 中的分组）
   - `type=2`：菜单/页面（实际的路由页面）
   - `type=3`：按钮（页面内的操作按钮权限）
   - `type=4`：接口（可选的细粒度 API 权限控制）
