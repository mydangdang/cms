> **版本**：v2.0
> **更新日期**：2026-02-03

## 📋 一、核心功能模块

### 1.1 认证与授权 🔥

#### 登录认证
- ✅ **用户名密码登录**
- ✅ **图形验证码**：防止暴力破解
- ✅ **JWT Token 认证**：无状态 Token 机制
- ✅ **Token 自动续期**：2 小时过期机制
- ✅ **退出登录**：清除 Token + 本地缓存

#### 权限管理（统一权限模型）🔥
- ✅ **动态权限驱动架构**：前端完全由后端权限数据驱动
- ✅ **三合一权限模型**：菜单 + 路由 + 按钮统一管理
- ✅ **权限类型**：
  - `type=1`：目录（Sidebar 分组）
  - `type=2`：菜单/页面（实际路由页面）
  - `type=3`：按钮（页面内操作按钮权限）
  - `type=4`：接口（可选的细粒度 API 权限）
- ✅ **权限树形结构**：支持多级嵌套
- ✅ **权限配置**：
  - `path`：前端路由路径
  - `component`：前端组件路径
  - `icon`：菜单图标
  - `is_hidden`：是否隐藏
  - `is_affix`：是否固定（标签栏）
- ✅ **角色权限分配**：一个角色可分配多个权限
- ✅ **用户角色分配**：一个用户可拥有多个角色

### 1.2 用户与角色管理

#### 管理员管理
- ✅ **管理员列表**：分页查询、关键词搜索、状态筛选
- ✅ **新增管理员**：用户名、密码、真实姓名、手机号
- ✅ **编辑管理员**：修改基本信息、重置密码
- ✅ **删除管理员**：软删除机制（权限码：AdminDelete）
- ✅ **状态管理**：启用/禁用
- ✅ **角色分配**：一个管理员可分配多个角色
- ✅ **按钮权限**：AdminAdd（新增）、AdminEdit（编辑）、AdminDelete（删除）
- ✅ **API权限**：AdminGetlist（列表API）、AdminAdd（新增API）、AdminEdit（编辑API）、AdminDelete（删除API）

#### 角色管理
- ✅ **角色列表**：分页查询、关键词搜索
- ✅ **新增角色**：角色名称、描述
- ✅ **编辑角色**：修改角色信息
- ✅ **删除角色**：检查是否被使用
- ✅ **权限分配**：树形权限勾选
- ✅ **按钮权限**：RoleAdd（新增）、RoleEdit（编辑）、RoleDelete（删除）、RoleAssignPermission（分配权限）
- ✅ **API权限**：RoleGetlist（列表API）、RoleAdd（新增API）、RoleEdit（编辑API）、RoleDelete（删除API）、RoleAssignPermission（分配权限API）

#### 权限菜单管理
- ✅ **权限列表**：树形展示所有权限
- ✅ **新增权限**：支持目录、菜单、按钮类型
- ✅ **编辑权限**：修改权限信息
- ✅ **删除权限**：检查是否存在子菜单、检查是否被角色使用
- ✅ **按钮权限**：PermissionAdd（新增）、PermissionEdit（编辑）、PermissionDelete（删除）
- ✅ **API权限**：PermissionAdd（列表API）、PermissionAdd（新增API）、PermissionEdit（编辑API）、PermissionDelete（删除API）

### 1.3 系统配置与管理

#### 系统配置
- ✅ **配置分组**：按分组管理配置项（0=未定义, 1=站点设置, 2=运营参数, 3=系统参数）

- ✅ **API权限**：ConfigGetlist（列表API）、ConfigAdd（新增API）、ConfigEdit（编辑API）、ConfigDelete（删除API）

- ✅ **任务列表**：任务名称、Cron 表达式、执行命令、超时时间、状态
- ✅ **任务管理**：新增、编辑、删除、启用/禁用

- ✅ **Cron 表达式**：标准 cron 语法
- ✅ **执行类型**：支持 API 和 CLI 两种执行方式
- ✅ **按钮权限**：CrontabAdd（新增）、CrontabEdit（编辑）、CrontabDelete（删除）、CrontabExecute（立即执行）、CrontabLogs（查看记录）、CrontabClearLogs（清空记录）

### 3.2 认证与安全

#### JWT 认证
- ✅ **Token 生成**：登录成功生成 JWT Token
- ✅ **Token 验证**：每个请求自动验证 Token（白名单除外）

- ✅ **参数验证**：验证器严格验证请求参数

### 3.4 认证与权限实现 ⚠️

**实现方式说明**：
- 项目采用 ThinkPHP 5.0 框架，受框架中间件体系限制
- 认证和权限逻辑直接在 Base 控制器中实现，而非独立中间件类
- 这种实现方式适合当前框架环境，具备相同的功能特性

#### Token 认证实现（Base 控制器）
- ✅ **Token 验证**：从请求头解析并验证 JWT Token
- ✅ **白名单机制**：登录接口、验证码接口无需 Token 验证
- ✅ **用户信息注入**：验证成功后将 admin_id、username、is_super 注入请求对象

#### CORS 跨域处理
- ✅ **允许源配置**：支持前端开发服务器（localhost:5173/5174）
- ✅ **OPTIONS 预检**：正确处理 OPTIONS 预检请求
- ✅ **凭证支持**：Access-Control-Allow-Credentials: true

#### API 权限验证
- ✅ **接口权限验证**：验证当前用户是否有权限访问接口
- ✅ **超级管理员放行**：超级管理员（is_super=1）跳过权限检查
- ✅ **权限码匹配**：通过 Permission 模型获取用户权限并与接口权限比对

## 🎯 六、关键创新点

### 6.1 动态权限驱动架构 🔥 核心创新

**传统方式**：前端硬编码路由、菜单、权限判断
**创新方式**：后端统一权限表驱动前端所有权限元素

```
┌─────────────────────────────────────────────────────────────┐
│                    传统权限控制                              │
├─────────────────────────────────────────────────────────────┤
│  前端：硬编码路由配置 → 硬编码菜单 → 手动权限判断             │
│  后端：接口权限验证                                          │
└─────────────────────────────────────────────────────────────┘

                            ↓ 优化

┌─────────────────────────────────────────────────────────────┐
│                  动态权限驱动架构 🔥                         │
├─────────────────────────────────────────────────────────────┤
│  1. 登录成功后调用 /getUserPermissions                      │
│  2. 后端返回完整权限树（type=1,2,3,4）                       │
│  3. 前端自动生成：                                           │
│     → 侧边栏菜单（type=1,2）                                 │
│     → 动态路由（type=2, path + component）                   │
│     → 按钮权限（type=3, v-permission 指令）                  │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 统一权限模型（三合一）🔥

**传统方式**：菜单表 + 权限表分离，维护复杂
**创新方式**：一张表统一管理菜单、路由、按钮

| 特性 | 传统方式 | 统一权限模型 |
|------|----------|--------------|
| 表数量 | 2 张（菜单表 + 权限表） | 1 张（权限菜单表） |
| 数据一致性 | 需要同步维护 | 自动一致 |
| 前端集成 | 需要多接口获取 | 单接口获取全部 |
| 维护成本 | 高 | 低 |
| 扩展性 | 一般 | 优秀 |

### 6.3 权限精细化控制 🔥

- **页面级**：通过路由权限控制页面访问
- **按钮级**：通过 v-permission 指令控制按钮显示
- **接口级**：通过权限码验证接口访问权限

#### URL 访问规则（ThinkPHP 5.0 约束）
- 格式：`http://api.bms.co/{模块}/{控制器}/{方法}?参数=值`
- 示例：`http://api.bms.co/admin/login/submit` → admin模块/Login控制器/submit方法
- 所有模块（admin、index等）均遵循此规则
- **不做伪静态处理**，直接使用 ThinkPHP 默认 URL 模式
- ThinkPHP 5.0 默认支持此规则，无需额外配置路由

#### API 设计：RESTfu
- 标准资源路径：GET /admin, POST /admin, PUT /admin/{id}, DELETE /admin/{id}
- 符合行业规范，易于理解
- 状态码规范：200 成功, 201 创建, 400 请求错误, 401 未认证, 403 无权限, 500 服务器错误


### 9.3 PHP 5.6 语法规范 🔥 重要

**⚠️ 严禁使用 PHP 7+ 语法特性！项目运行环境为 XAMPP (PHP 5.6)**

#### ❌ 禁止使用的 PHP 7+ 语法

| PHP 7+ 语法 | 说明 | PHP 5.6 替代写法 |
|-------------|------|------------------|
| `$var ?? $default` | 空合并运算符 | `isset($var) ? $var : $default` |
| `$var ??= $value` | 空合并赋值 | `if (!isset($var)) $var = $value` |
| `$a <=> $b` | 太空船运算符 | 使用三元表达式实现 |
| `function foo(int $a): int` | 标量/返回类型声明 | 移除类型声明 |
| 匿名类 | 匿名类语法 | 使用命名类 |
| Group use | Group use 语句 | 单独 use 语句 |

#### ✅ PHP 5.6 兼容写法示例

```php
// ❌ PHP 7+ 写法（禁止）
$value = $data['key'] ?? 'default';

// ✅ PHP 5.6 写法
$value = isset($data['key']) ? $data['key'] : 'default';

// ❌ PHP 7+ 写法（禁止）
function getUser(int $userId): array {
    // ...
}

// ✅ PHP 5.6 写法
function getUser($userId) {
    // ...
}

// ✅ PHP 5.6 写法（推荐）
$items = array(1, 2, 3);  // 虽然 5.4+ 支持短数组，但推荐使用 array()
```

- **本地开发**：本地 PHP 版本可以较高，但代码必须兼容 PHP 5.6
- **运行环境**：XAMPP 集成环境，PHP 版本为 5.6
- **系统测试**：所有测试必须在 XAMPP 环境下进行
